# Lessons

Rules learned from past mistakes. Read this file at the start of each session.

<!-- Append new rules below as mistakes are corrected. One concise rule per entry. -->

- **Ship tests in the same commit as the code they cover.** Splitting a fix from its regression test leaves a commit that cannot demonstrate what it claims, and a bisect that lands on an unproven fix.
- **Before overwriting a figure recorded in a project's docs, trace where it came from.** When a fresh measurement disagrees with a written one, find the evidence behind the written one first — the reason for the discrepancy is often more informative than the corrected number, and sometimes it is not an error at all. If a figure has no evidentiary home, that absence is itself the finding.
- **A truncated view is not the data.** A `head`, a `most_common(6)`, a scan scoped to one year, a `tail` of a log — reading absence from any of them as absence from the dataset has produced three confident, wrong, load-bearing claims in this project alone ("not one burst holds a 4 or a 5", "darktable has not written to this archive", "the per-image cost is dominated by the decode"). Before asserting that something does not occur, count it over the whole population and say what the denominator was.
- **A rule recorded in one place must be applied everywhere it holds.** "The process counters are not exports" was written down for the Capture One catalog and never applied to the `.cos` reader that already used them — a 32×-wrong value sitting in live code beneath a document that refuted it. When a finding corrects how one reader interprets a source, grep for every other reader of that same source before closing the item.
- **A completion updates the items that cite it, not only the item it closes.** Twice in one project a finished piece of work left a citing document asserting the opposite for days — and the stale copy is the one a reader meets first when scanning for what is outstanding. After marking something done, search the repo for the claim it just falsified.
- **Corrections belong in a durable index, not only beside the claim they fix.** Striking through a wrong figure where it appears is right for the reader who lands there; it is useless for seeing that six corrections in two days share one mechanism. Keep both: the inline note for locality, and a dated list so the pattern is visible to whoever looks next.
